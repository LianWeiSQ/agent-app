# 面试入口：先讲经历，再接受技术追问

不再从头背一百多道题。准备顺序是：经历与项目 → 一条任务链路 → 两个深入主题 → 一个真实案例 → 证据边界。

## 三种阅读深度

| 可用时间 | 怎么读 | 目标 |
| --- | --- | --- |
| 10 分钟 | [开场与项目](01-开场与项目问答.md)，再看[事实边界](03-事实边界与证据.md) | 讲清做了什么，不说过头 |
| 40 分钟 | 加上[Harness 追问](02-Harness追问.md)和[执行资源答辩](../../infra/interview/01-执行资源答辩.md) | 能讲状态、资源、恢复和取舍 |
| 系统准备 | 沿下表进入技术主文，补案例与测试证据 | 经得起连续追问 |

## 如何讲，而不是如何背

先直接回答，再解释一条机制。面试官继续问，才展开故障窗口、替代方案和验证方法。每个名词都应该能回答一个具体问题，不能用“我们有完整的治理能力”替代实现细节。

主回答中的第一人称是根据本人陈述整理的口述稿。具体提交、上线范围和量化结果未补齐时，不扩大口径。论文与 RSI 放在研究附录，不主动占用项目介绍时间。
