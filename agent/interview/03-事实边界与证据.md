# 事实边界：哪些能说，哪些还要拿证据

本页把项目优势放到能接受追问的位置。2026-10-08 已读三份飞书正文，并核对[两份 Harbor 历史结果](../sources/Harbor样本核对.md)；没有重新审计项目源码、访问生产集群或复跑评测。

## 两版准备稿的冲突如何处理

| 主题 | 文稿中的差异 | 本库采用的口径 | 还需要什么 |
| --- | --- | --- | --- |
| Max Step | 一版写 Web 12、Core 50；另一版按 Python HTTP 10、Rust HTTP 80 分开 | 不设置“全平台当前默认值”；回答时先确认仓库、入口、版本和有效配置 | 对应提交、配置优先级、运行时有效值、终止测试 |
| 上下文重构 | 总手册陈述 OpenHarness 已完成；另一版在 AaaS 未找到同名实现 | 可能属于不同仓库；保留实现陈述，不推定全部产品已接入 | 代码版本、测试报告、入口覆盖、本人改动 |
| YiBuddy | 后续经历明确是端侧；早期规划包含云端工作台和固定协作 | 经历按端侧主线讲，设计范围与当前产品版本分别说明 | 同一版本的架构、运行截图与验收范围 |
| 产品共用 | 有文稿写共用 AaaS 后端；另有说明不能认定 Harness 相同 | 只谈能确认的协议或模块复用，不宣称三产品同一部署 | 依赖关系、实际模块或部署说明 |
| Harbor 环境 | 讨论过接沙箱平台；本地样本记录是 Docker | “接入方案”与“实际试验环境”分别记录 | 远端环境适配与同题对照试验 |
| GPU 执行 | 一处倾向 GPU 转作业，专题补充短 GPU 任务可在沙箱运行 | 按时长、恢复与治理需求分流，不按有无 GPU 一刀切 | 实际资源配置、调度与取消验证 |

修订号较大不代表所有内容更准确；不同文档修订号也不能跨文档比较新旧。优先看所指系统和证据，再看明确更正关系。

## 将“做过”分成可检查的四层

| 层次 | 最低证据 | 可以证明什么 |
| --- | --- | --- |
| 设计 | 版本化方案、约束与验收标准 | 方案和取舍已经明确 |
| 实现 | 对应代码、测试、责任记录 | 某版本具备特定实现 |
| 验收 | 环境、步骤、运行结果与产物 | 在这些条件下链路成立 |
| 生产效果 | 发布范围、真实样本、基线与指标 | 线上范围内的收益与限制 |

一张架构图属于设计说明。截图能证明页面和某次操作可见，但不能单独证明故障恢复、多租户隔离或性能。

## 适度配图：目前有什么，还缺什么

本轮增加三张可公开说明图：[任务到成果](../projects/README.md)、[沙箱生命周期](../../infra/sandbox/01-创建预热与就绪.md)、[评测改进](../07-Harbor评测与持续改进.md)。均有可编辑规格和产物校验，不是产品实图。

三份来源正文没有嵌入图片。因此，真正用于佐证产品开发的实图还需补充并确认公开范围，不能用生成图填补这项证据。

| 优先级 | 应补材料 | 图注必须说明 |
| --- | --- | --- |
| 1 | 智算云同一任务的输入、工具过程和文件下载 | 产品版本、采集日期、关联任务、哪些字段已脱敏 |
| 2 | Harbor 试验详情与验证结果，附脱敏结果摘要 | 任务、模型/Harness 版本、环境、是否单样本 |
| 3 | YiBuddy 工作台与授权/干预过程 | 端侧还是云侧执行、对应版本、演示边界 |
| 4 | AI4S 产物与来源/方法对应页 | 示例还是实际业务、验证规则、可公开范围 |

每个项目选一组能讲透的证据即可。不要把不同任务的输入与结果拼在一起，不用原型图证明已开发，不用单次通过证明全平台成功率。

## 真实案例怎样补进来

### 案例候选 A：工具原文有了，下一轮却读不到

材料依据较明确，可先讲机制：结果生成与后续读取发生在不同文件系统。下一步补本人检查的调用、路径映射改动、完整输出读取回归。若没有事故时间线，只说项目接入与验收问题，不编造线上严重故障。

### 案例候选 B：评测在安装阶段失败

已经核对一个任务还没进入 Agent 执行就失败的结果记录，可以用它解释为什么环境可用性与模型能力要分开统计。另一个成功样本有阶段耗时和 6 项测试通过记录。它们不是完整试验分母，也不证明已经通过改动获得收益。

### 案例候选 C：设计跨进程恢复

适合系统设计深挖，不能自动成为“已解决的生产故障”。补齐提交、故障注入和副作用次数后，才把相应能力从设计更新为实现或验收。

通用模板：[实战与案例](../10-实战题与案例模板.md)。新案例写清“我做的动作、团队完成的工作、证据支持的结果”，并注明仍未验证的范围。

## 公开版与私人底稿

公开版保存高层架构、工程方法和脱敏来源摘要。原始飞书内容、内部安全缺口、账号地址、客户和个人信息仍留在本地私有区。图片尚未获得公开确认时不提交；确认后也要逐图检查，而不是只遮住姓名。
