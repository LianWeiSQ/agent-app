# RSI：从反馈到受控改进

依据：[会话中的研究兴趣](sources/会话摘要.md)。这里的 RSI 指递归自我改进方向的讨论，不表示已经做出了自动持续提升的系统；不同文章对这个词的定义可能不同。

## 问：Agent 多用几次，就会自动变强吗？

不会。保存更多对话不等于学习出更好的策略。需要有明确可修改的对象、评价标准、候选对比和晋级规则，才能知道改动有益还是过拟合。

应区分四件事：任务内反思、跨任务记忆、Harness/工具/Skill 的改进、模型权重训练。前三者可以不修改模型权重，也不能都称为模型训练。

## 一个可验证的流程

从经过授权和脱敏的失败记录中选择问题，人工或 Agent 提出原因假设；在隔离分支或环境中修改候选；固定基线、预算和任务条件比较；通过独立验证后才发布。

第一次可以只允许修改一份 Skill 的说明或一个工具的错误反馈。范围小更容易解释收益，不要先开放整个运行时的任意自改权限。

## 两类评估为什么要分开？

运行时评估回答“这次任务是否完成”；改进评估回答“候选版本在一组未见任务上是否优于基线”。通过当前任务不等于改动值得长期保留。

候选不能修改自己的验证器、基线或晋级标准。调参任务与最终留出任务分开；反复查看留出集也会逐渐污染它，需要管理使用次数和更新策略。

## 问：怎样避免只优化分数？

同时约束安全、成本、尾延迟和回归。要求改动指出收益来自哪个机制，并保存失败案例。指标突然提高时也检查是否发生答案泄漏、环境变更或判分绕过。

对工具权限、安全策略和数据外发等高风险对象，保留独立审核。自动生成补丁不代表自动授权上线。

## 问：什么时候才考虑模型微调？

先排除数据缺失、工具难用、环境失败和流程设计问题。若剩余问题稳定集中在模型行为，且已有合规、高质量数据，才讨论训练。

训练需要独立的数据版本、划分、评测、发布和回退流程。不能把用户全部工作资料直接收进训练集，也不能用训练集上的得分代替泛化效果。

## 最小实验计划

选一类重复发生的问题，保留原策略作基线，候选只改变一个主要因素。报告多次运行的分布、失败类型和改动成本。没有足够优势就保留基线，不强行宣布成功。

这部分面试可以作为研究方法和下一步探索，主体仍应是 [Harbor 的真实实践](07-Harbor评测与持续改进.md)。
