# Agent 会话摘要与证据边界

来源：会话 **last dance** 的可见讨论与既有本地面试稿；结合 **last dance -infra** 中用户对经历顺序的明确更正。整理时间：2026-10-08。仅归纳，不上传原始聊天、私有文档和内部代码。

## 本人明确陈述

- 姓名是廉威；在本次整理时自述六年研发经历。
- 早期在华为从事 Go 后端与云端微服务工作，后在上海智算从事 Agent 架构相关工作。
- 项目结构为 YiBuddy、智算云通用智能体、AI4S 科研垂类智能体。
- 经历顺序先是云端 AI 和自研 Harness 设计，之后参与 YiBuddy 端侧 Agent 开发。
- 做过基于 Harbor 的 Agent 评测任务，用于评估平台能力和支持迭代。
- 科研只是垂类；平台介绍应覆盖通用任务，不能将全部项目缩成科研 Agent。
- 论文调研是兴趣，不作为已完成的工作成果。
- 希望回答有具体机制与取舍，不堆砌术语，后续继续补真实案例。

这些属于本人陈述，不等于本库已核验每个模块的代码贡献或生产运行结果。

## 讨论如何推进

开始讨论长任务恢复：Bridge、Provider、Tool、Approval、Question 的崩溃位置如何区分。随后讨论 Step 上限、反复调用、终止条件和执行预算。

面试准备阶段逐步分清项目定位、个人职责与平台能力，重点转向云侧 Harness、沙箱隔离、事件流、文件交付及副作用。

评测阶段形成 Harbor 的环境、Agent 适配、轨迹、验证器与回归思路。进一步讨论 RSI，但没有足够证据证明已形成自动自我提升系统。

最近讨论招聘岗位，明确“评测 Agent”和“开发 AI 测试工具”有能力交集，但不能等同为相同工作年限。

## 哪些只能作为设计

完整跨实例接管、执行租约、fencing token、持久审批与追问、Effect Receipt、迁移回滚测试矩阵，在没有具体交付证据前按方案介绍。不要把用户要求建设的能力当成已完成。

## 已有笔记能支持到哪里

已有本地材料描述过 Harbor 单次任务通过和安装阶段失败的样本。这次没有把原始日志与可重放环境放进公开仓库，因此正文只说明如何分类和验证，不发布通过率、性能提升或大规模平台结论。

## 暂不纳入

个人服务器运维、听页公网部署、磁盘清理、金融讨论、他人简历、招聘私人通信。与本库主线无关的会话内容不为了“完整”而复制。

## 待补证据

1. 亲自负责模块的公开说明或可公开的改动摘要。
2. 一个真实故障的时间线、排查路径和回归验证。
3. 一个 Harbor trial 的脱敏证据与版本信息。
4. 哪些架构方案已经实现，哪些还停留在规划。
