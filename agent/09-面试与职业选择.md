# 面试怎样讲真实经历，怎样判断测试开发机会

来源：[本人经历](sources/会话摘要.md)与[公开岗位说明](sources/公开参考.md)。这是一份当前策略，不是对录用、薪酬或职业发展的保证。

## 问：最值得保留的个人主线是什么？

Go 云服务 → 云端 Agent / 自研 Harness → YiBuddy 端侧实践 → 进一步理解执行资源与推理服务。

强项是把任务运行与服务端工程连起来。推理部署、GPU 调优的学习可以补这一条线，不必把自己同时包装成算子、训练、推理、Agent 全栈专家。

开场先讲经历与解决的问题，面试官感兴趣再展开一个案例。不要把十个技术词当成十项贡献。

## 问：为什么考虑 AI Agent 测试开发？

Agent 平台经验有助于构建测试工具，后端经验有助于复现复杂服务问题，Harbor 有助于理解评测与证据。但当前主要是研发背景，不能把六年研发直接写成五年以上 QA。

“评测 Agent”关注被测智能体能否完成任务；“用 Agent 改进测试”关注如何帮助测试生成、复现、定位与回归。两者可衔接，需要补上实际工具成果。

## 问：SDET 和普通开发差在哪里？

都可能写平台和修源码。研发主要交付产品能力，SDET 主要交付可信的验证方法、自动化工具与质量判断。

同一个命令超时问题，研发需要修正执行逻辑；测试开发还要稳定制造故障、验证命令是否仍运行、判断重试是否重复写入，并形成长期回归。

如果只是会写脚本，而不能说明哪些风险必须测、如何判定结果、为何值得阻断发布，还不足以证明高级测试开发能力。

## 问：测试的发展会比开发更好吗？

不能按名称下结论。对已有研发积累的人，更值得考虑的是自动化基础设施、可靠性验证、性能分析和 AI 评测平台；日常主要执行用例的岗位，可能与当前成长方向不一致。

面试中询问最近半年真实项目、入职后独立负责的组件、优秀成员的成长路径。不要因公司品牌就默认有 GPU 深度、较少压力或更容易转岗。

## 当前岗位准备的优先级

优先准备云原生 Agent 测试工具方向；模型测试方向作为扩展了解；暂不集中投入 CUDA 底层题。具体学历、QA 年限与语言要求需要招聘方确认，不猜测可以豁免。

Agent SDET 与 Deep Learning SDET 的职责可能相似，但公开 JD 的测试对象不同。以具体招聘编号确认，不把一个岗位的学历或加分项套给另一个。

## 三个值得准备的故事

1. **Harbor 评测：** 为什么选这批任务，怎样判分，如何区分安装失败和任务失败，一次改动怎样验证。
2. **云服务故障：** 现象、影响、证据、排除的假设、改动、回归。只选亲自参与的。
3. **架构取舍：** 当前能做什么，为什么先补某项能力，放弃什么，最终如何验收。方案和交付分开。

每个故事准备 30 秒结论、2 分钟主线、追问时的证据。未知数据直说待补，不用虚构数字让回答显得完整。

## 一个节省精力的两周安排

| 阶段 | 投入建议 | 产出 |
| --- | --- | --- |
| 确认岗位与筛选条件 | 2 小时 | 编号、团队、研发内容、面试语言 |
| 整理 Harbor 案例 | 4 小时 | 可讲清的 trial 与失败分类 |
| 整理云服务故障 | 3 小时 | 时间线、复现方法和回归 |
| Python 测试基本功 | 3 小时 | 日志解析、超时、并发、fixture 与断言 |
| 最小 AI 测试工具 | 3 小时 | 输入失败轨迹，输出有证据的归因候选 |
| 推理链路补课 | 2 小时 | 知道请求慢在哪一层 |
| 中英文模拟追问 | 3 小时 | 能脱稿解释而非朗读术语 |

这是准备计划，不是承诺两周补齐高级 QA 或 GPU 生产经验。优先复用已有项目，不为了面试做多个无关联 Demo。
