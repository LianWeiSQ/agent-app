# 我做了什么：三个项目与一条经历主线

这是快速总览。完整展开见[三个项目页](projects/README.md)，口头练习见[开场与项目问答](interview/01-开场与项目问答.md)。

依据：[本人经历陈述与更正](sources/会话摘要.md)。这是个人口径整理，不是公司发布材料。

## 问：怎样介绍自己，不显得在背组件清单？

可以从这段开始，再根据实际面试调整：

> 我叫廉威，有六年研发经历。之前在华为做 Go 后端和云端微服务，后来在上海智算做云端 AI 产品，负责自研 Harness 的架构设计，并参与相关研发。之后参与 YiBuddy 的端侧 Agent 开发。云端和端侧面对的资源与权限不同，我关注的是任务如何执行、出了问题怎样定位，以及运行时和执行环境之间怎样划清边界。

“六年”是 2026-10 整理时的自述，后续按真实履历更新。不要在开场就宣称每个恢复、安全和评测能力都已完备。

## 问：三个项目之间是什么关系？

| 项目 | 场景与定位 | 讲解重点 |
| --- | --- | --- |
| 智算云 | 运行在云上的通用 Agent 服务 | 云端任务、Harness、隔离执行、文件产物与服务治理 |
| AI4S | 科研垂直方向的 Agent | 领域工具、数据与成果验收；科研是场景约束，不是全部平台定义 |
| YiBuddy | 后续参与的端侧 Agent / 工作助手 | 本地文件和软件、用户授权、端云边界以及执行环境差异 |

它们可以共享设计经验，但不能据此认定共享同一套代码、同一状态库或所有功能完全一致。回答复用问题时，应说明实际复用的协议或模块。

## 问：智算云和一个普通 Agent Demo 差在哪里？

以用户上传材料并生成报告为例：模型需要读文件、执行代码、检查结果，最后把成果交付。循环能跑只是其中一段，还要有人管理任务身份、访问权限、隔离环境和文件寿命。

可以按三层说明：

- 云侧服务接收请求、处理身份与配额、向用户提供进度和成果入口。
- Harness 组织上下文并驱动模型与工具，维护任务语义。
- 沙箱平台管理实际执行环境、资源、文件通道与生命周期。

不要贬低所有其他 Agent 都只是 Demo。对比对象应限定为没有这些治理能力的简单实现。

## 问：到了端侧，为什么不能直接照搬？

本机已经有用户的软件、文件和登录状态。让 Agent 直接利用它们比较方便，但权限范围也更敏感；离线、休眠、应用退出、资源占用会影响执行。云端则更强调租户、集中治理和资源池。

共通的是任务、工具和状态语义；需要重新判断的是执行位置、授权交互、工作区及端云数据流。端侧不天然安全，云侧也不天然适合所有任务。

## 问：哪些算我的贡献？

讲本人做过的架构判断和实际动作，分清“我设计”“团队实现”“我参与联调”“仍在规划”。准备一份模块与证据对照，不用“我负责整体”替代所有细节。

当前仍待补：具体改动、一次真实故障、评测前后结果。没有证据的生产规模和成功率不补写。

## 问：真实规划体现在哪里？

讨论过的云端工作台方案优先解决连续使用：资料独立上传、成果编辑、历史复用、专业 Agent 配置。再逐步验证有限协作和长任务，而不是一次并入所有客户端与自由调度。

规划的价值在于取舍及验收条件；方案完成不等于产品发布。讲清现状、用户缺口、放弃了什么、如何分阶段验证，比列功能更有深度。
