# Tool、Skill、MCP 与审批怎样配合

依据：[会话摘要](sources/会话摘要.md)、[公开参考](sources/公开参考.md)。这里按职责说明，不断言某个框架版本自动覆盖全部能力。

## 问：三个词的边界是什么？

Tool 是可以执行的操作，必须有清楚的输入、输出、错误和副作用约定。Skill 描述某类任务怎样做，可能附带资源与脚本。MCP 提供接入外部能力的协议；接入成功不等于已经解决租户授权、隔离或可靠性。

Skill 的文字不是权限凭证。模型看到“运行脚本”后，仍应通过工具与执行权限检查；外部工具返回的文本也不能升级成系统指令。

## 问：一个好工具接口应该告诉模型什么？

不仅是函数名，还包括适用条件、必填参数、限制、结果结构及失败含义。例如命令执行不能仅返回一段字符串，至少要区分请求被接受、命令已启动、退出码、输出是否截断、产物位置及是否可以查询。

错误要能指导下一步：参数错误适合修正，权限拒绝不能靠重复调用解决，网络超时可能是结果未知，资源不足可能需要排队或调整规格。

## 问：MCP/Skill 怎样从接入变成平台能力？

注册只是开始。还需要明确租户范围、版本、凭证存储、允许的工具、额度、超时、审计和退出机制。任务应记录当时使用的配置版本，否则重放时可能已换了工具实现。

远程服务初始化失败、能力列表变化、接口 schema 与实际返回不一致，都应有独立错误分类，不能统统变成模型失败。

## 问：哪些动作需要审批？

按副作用和信任边界划分，而不是按“是否 Shell”划分。读取公开信息通常风险较低；发送消息、删除数据、写入外部系统、扩大网络或文件权限，需要明确授权范围。

审批卡展示操作对象、关键参数、外部影响、可逆性和有效期。用户改了参数，旧审批失效或需要按规则重审。审批只是允许尝试，并不保证执行成功。

## 问：怎样处理提示注入？

截图、网页、检索结果和工具输出都可能包含看起来像命令的文字。它们是待分析数据，不因进入上下文就有权要求上传文件、读取秘密或发送通知。

限制工具能力和数据出站范围，隔离凭证，让执行层检查权限，并验证越权测试。只在 Prompt 中写“不要上当”不能成为唯一防线。

## 问：模型输出错误参数怎么办？

先用 schema 校验和业务规则拒绝不合法动作，再把明确错误返回给模型。有限次修正后仍不合法就停止或请求澄清。不要为了“提高成功率”自动猜测删除对象、收件人或付款金额。

调用的逻辑身份与具体 attempt 分开，重试沿用同一逻辑动作的幂等机制。详见 [持久状态与故障恢复](03-持久状态与故障恢复.md)。

## 验收用例

覆盖参数畸形、过期审批、权限撤销、伪造工具指令、输出截断、凭证泄漏、重复请求和结果未知。衡量任务效果的同时，单独报告危险动作误执行，不能用较高总分抵消安全失败。
