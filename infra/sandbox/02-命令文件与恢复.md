# 沙箱执行：命令、文件和恢复是三件事

## 1. 模型提出工具调用以后，谁真正运行进程

Harness 校验工具及参数，使用会话保存的环境绑定定位工作区，再调用执行接口。沙箱内的执行代理启动进程，回传标准输出、错误输出与退出状态。模型只是提出动作，实际进程由执行服务创建。

containerd 等容器运行时负责把容器启动起来；execd 这类代理负责在已有环境中处理命令和文件。人工终端可以另走 Pod Exec，预览服务可以另走 HTTP/WS 代理。三条路径的鉴权、审计和断连语义应分别确认，不统称“远程执行”。

## 2. 成功要看哪一层

请求成功送达，不等于命令已启动；命令退出码为零，不等于预期文件完整；文件存在，不等于用户有权下载；能下载，不等于内容满足目标。

例如生成报告，最小验收应检查约定路径中的文件存在、格式可读、大小和内容符合要求，并能通过用户授权的下载路径读取。工具把这些证据回填任务，Harness 才继续判断是否完成。

## 3. 超时不能直接当作没有执行

前端超时、代理断线、命令自身超时与实例消失是不同事件。若命令已经写了文件，调用方却没收到响应，直接重发可能启动第二个写入者。

有查询能力时，按命令身份确认仍在运行、已经完成或失败。commandId 仅是线索；是否跨代理重启保留、是否参与去重，必须检查协议，不能看到字段就宣称恰好一次。无法确认时保存 unknown，并限制自动重试。

取消同样要区分请求受理、进程组退出和外部效果是否已发生。脚本发出的外部请求不会因为取消本地进程就自动撤销。[副作用恢复](../../agent/03-持久状态与故障恢复.md)解释上层如何处理。

## 4. 三种重启，三种恢复对象

| 故障 | 可能还在的东西 | 恢复前先确认 |
| --- | --- | --- |
| Harness / API 进程重启 | 远端沙箱、文件、已执行命令 | 任务所有权、环境绑定与上次动作结果 |
| 执行代理或容器进程重启 | 某些挂载文件、集群资源对象 | 原进程是否消失，命令状态是否可查询 |
| Pod 删除或节点故障 | 已持久化任务、持久卷或已上传产物 | 数据实际存活、卷可重挂、环境可重建 |

同一 Pod 中容器重启与 Pod 被删除重建，对临时卷的含义不同。持久卷的可恢复性又受存储后端与挂载条件限制。不能把“有卷”概括成任何故障都不丢数据。

任务可继续，往往是用保存的输入和阶段成果重新进入一个安全步骤；原进程无损续跑则需要执行后端或程序自身的检查点。两者验收标准不同。

## 5. 等审批时，资源怎样处理

短等待保留环境通常更快，但仍计算资源成本；长等待可以先保存任务状态、必要文件与环境版本，再回收计算，用户回复后重新建立环境。

这是一种资源策略，不是所有后端已有的暂停功能。还需解决最长等待时间、租约由谁续、保存失败能否回收、恢复失败怎样告知用户。进程冻结可能继续占内存和 GPU，也不是免费暂停。

## 6. 工作区与最终产物分开管理

工作区是工作台：输入、脚本、中间结果、日志和临时输出都会出现。最终产物是对用户的交付承诺，应该有稳定身份、归属、校验和及保留策略。

可采用先保存不可变文件并核对，再提交产物记录的方式。没有提交引用的孤儿文件由清理处理；已经对用户承诺保留的文件不能跟随临时沙箱 TTL 一起消失。文件操作还要处理路径穿越、符号链接和访问权限，不能只判断路径以某个字符串开头。

## 7. GPU 任务什么时候转作业系统

短时交互式图像处理或模型评估，可以使用申请了 GPU 的沙箱。数小时训练、多卡协同、需要排队、失败重试与检查点的任务，更适合独立作业生命周期。

Agent 保存 jobId、观察状态并取得成果，不需要让模型频繁询问“做完了吗”。取消 Agent 是否同时取消作业要在产品语义上明确；资源释放要看作业系统的实际状态。这里不声明已有大规模 GPU 调度实践。

## 8. 用小实验确认执行语义

在授权的测试环境执行“写入标记、等待、再写完成标记”的无害脚本。分别断开输出连接、发取消、重启执行代理，观察进程、文件和查询接口；把各阶段状态记录下来。不要用有真实外部写入的脚本测试不确定的重试语义。

这能比接口名称更直接地说明：断连后命令是否继续、取消是否覆盖子进程、文件能保留到哪一层。随后再为幂等和节点故障设计独立用例。
